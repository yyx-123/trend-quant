## 1. 全局实现决策（跨阶段，先记在这里）

1. **新表 DDL 全部放 `db.py` `_init_tables`**（engine_* 6 表、gateway_audit、
   portfolio 2 表、research 5+2 表、module_drafts、holdout_tokens、live 清单表），
   与存量同一模式（CREATE TABLE IF NOT EXISTS），保证任何 Database 实例
   （含测试隔离库）建库即有表。纯新增、对存量表零改动。db.py 的 God class
   拆分按架构稿"顺手做、不单独立项"处理——本期不拆，新增**访问逻辑全部
   落在各层自己的 store 模块**（engine/store.py、research/ledger.py 等），
   不再给 db.py 加业务方法；仅新增一个公开 `connect()`（`_connect` 的公开
   别名）供新包取连接。
2. **append-only 的落实 = 触发器列白名单**：内容字段（spec/hypothesis/
   verdict 证据等）UPDATE/DELETE 一律被库层触发器拒绝；生命周期字段
   （status、final_verdict、reasoning 等）走白名单列允许更新，且状态机
   由代码层强制非法转移拒绝。这与详设"代码层只有 insert/select + 触发器
   拒 UPDATE/DELETE"的意图一致——状态机落库必须留更新通道，通道收到最窄。
3. **涨跌停基准价口径澄清**：详设 §3.2 写"raw close(t-1) × 对应调整因子"，
   括号内"与交易所口径一致"为权威——按本项目因子语义
   （`qfq(t) = raw(t) / Π_{ex_date≥t} f_i`，core/adjustment.py），除权日 t
   的交易所参考前收 = `raw_close(t-1) / f_t`。实现按 `/ f_t`（不是 ×）。
4. **回测数据冻结（决策 A3）的进程边界**：冻结计数是**进程内**计数器
   （并发池与调度器同在 app 进程时生效：run 优先、日更/指标重建顺延）。
   独立 CLI 进程发起的 run 与 app 调度器不共享计数——一期可接受，
   因为研究 run 统一经 research worker（app 内）发起；记入风险表。
5. **测试口径**：存量 1248 项不得回归；新增测试按现有 markers 分层
   （unit/integration/api/slow）。统计判定器的 golden 对拍 = 与参考实现
   （标准库独立写法）逐值比对 + 论文代数性质断言，不依赖 scipy
   （项目无 scipy 依赖；Φ/Φ⁻¹ 用 statistics.NormalDist / math.erf）。
6. **本地全量数据原则**：本地调通流程用小样本/合成数据；真实全库
   sample 窗口（2015–2024）的 v1+benchmark 跑批以 scripts + slow 测试
   形式提供，产物（指标对比）记入本日志，曲线数据落本地 data/ 目录
   （不进 git）。

### 阶段 1 ✅（2026-09-23）

交付：`gateway/`（panel 面板 as-of 强制 / tradability 涨跌停停牌推导 /
metadata / audit 留痕 / BoundGateway 受限句柄）；`engine/`（profiles

`core/run_freeze.py`（决策 A3 进程内冻结计数）。

实现期发现/裁决（全部记录在案）：
1. **T+1 滚动时点**：初版在 settle 滚动导致当日买入当日快照即显示可卖
   （golden 测试当场抓住）。改为 `engine.begin_day()` 在次日开盘滚动，
   日结快照如实记录"当日买入 sellable=0"。
2. **现金逐手递减是设计行为**：详设 §4.2"现金校验不足 → 逐手递减"，
   递减到非零仍成交；测试按此校准（5000 元买 10000 股 → 成交 400 股）。
3. **停牌日仍推导涨跌停价**：复牌日与次日判定要用最近可得前收，
   suspended=True 与 limit 价格共存（测试锁定）。
4. **旧引擎 MACD 有 35 根预热保护**（max(fast,slow)+signal），新栈
   parity 驱动同口径复制；L3 `macd_cross` 模块（阶段 2）同样遵守。
5. **空仓计息不计入 parity 对拍**：1% 计息是详设 §4.4 新引入口径
   （§5.12.3 审计 A 项接纳），parity 用零息 profile 隔离引擎力学，
   计息正确性由 golden 测试单独锁定（252000 元一天利息恰 10 元）。
6. **止损盘中成交不叠滑点**：详设 §4.2"按 stop_price 成交/跳空按开盘"
   字面落实（条件单触发价即成交假设，用户已确认可行性）；fills 的
   slippage 字段记 0。
7. **止损 unfilled 只在"触发但被阻塞"时落账**（跌停/T+1/停牌三种），
   未触发不落——"没发生的交易不是错过的交易"；次日重试由回测器
   每日重评估天然承担（止损价每日重算，详设 §4.2 口径）。
8. **引擎取数路径**：回测器一次性经 L1.5 面板取全窗口数据（as_of 锚定），
   逐日转供引擎（tradability 卡 + bar），引擎不逐日调 gateway——性能
   决定的工程实现，数据面仍全走 L1.5（详见阶段 2 DayContext 说明）。

测试：新增 50 项（gateway 14 / fees+matcher 17 / stops 对拍 6 / golden 7 /
parity 3 / run_freeze 含内），本阶段 76 项全绿（含阶段 0）。

  不是 bug（无组合约束的 v1 在 2015 股灾段满仓硬扛）。

实现期决策/偏离（全部在案）：
1. benchmark 符号按本地数据可得性调整：511010（国债ETF）/518880（黄金ETF）
   本地无数据 → 60/40 的债腿改为现金（年化 1%，与引擎空仓计息同口径，
   "60/40 股现"）；动量轮动的黄金腿改 518850。YAML 内有注释。
2. 元模块注册键带插槽（"slot:any_of@1"）——同名元模块可存在于多插槽。
3. equal_weight_universe  benchmark 用流动性 top-50 近似（874 只全摊在
   100 万下大量标的不够一手，YAML 注释注明）。
4. 无组合约束的 v1 在长窗口产生大量 insufficient_cash 未成交记录
   （160k 行/run）——这是"无 slot_limit 如实复刻"的诚实结果（错过的
   交易是研究素材），也实证了组合约束正是第一个实验要测的东西。
5. 性能优化三件事：L1 新增窗口批量读 `load_market_data_window_many`
   （SQL 下推，行情载入减半）；matcher 现金校验解析式直达（替代逐手递减
   热循环，费用函数调用从 10.9M → 3 万级）；可交易性向量化 + 只算运行
   窗口（扩展轴算前收，运行日子集输出，首日涨跌停判定不丢前收）。
6. ATR 面板回测期一次性预计算（因果 rolling），模块 O(1) 读当行。
