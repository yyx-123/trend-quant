## 方法（为什么可以确定没有改坏代码）

1. 用 **`tokenize`** 定位 `COMMENT` 与 `STRING` token，只在它们的字符区间内替换——
   代码 token 一律不进入替换范围；
2. 替换规则是**删除型**（前缀 + 编号 + 可选的"复核/验收"词 + 紧随的冒号），
   仅追加"空括号 / 悬空标点"收拾，不做空白归一、不做换行重排、不碰缩进；
3. 三轮**校验**：
   - 代码 token 等价：对全部改动文件比较 `HEAD` 与工作区的非注释/非字符串 token 序列，
     **完全一致**（唯一两处例外是本文件第 2、3 项的有意改动）；
   - 字符串 token 逐条审阅：62 个被改的字符串 token **全部是 docstring**，无一条是数据串
     （即不涉及任何错误文案/常量值）；
   - ruff：`(file, rule)` 集合与基线 worktree **78 / 78 完全一致**（新增 0 条）；
   - 测试：钉子与相关子集 174 项通过；全量套件 TERMINAL_PLACEHOLDER。
4. diff 规模：`src/` 53 个文件 `+233 / −229`（近乎 1:1 的注释文本替换）。
