# 最终报告归档：R1-R20 的逐轮追加内容（新版 final-report.md 的前身）

> 保留旧版按轮追加的「新增待决策点/遗留问题」章节；新版 final-report.md 已把仍在开放状态的项汇总进第五节。

## 七之九、R20 新增待决策点

- **⚠ 因子清空守卫的运维含义（需你知悉）**：本轮 P1 的修复把"上游返回空却本地有因子"从
  **静默清除并重物化**改为**拒绝 + 告警**。若 vendor 将来确实换口径/清空因子（真"因子消失"），
  现在需要人工确认后手工处理（脚本入口：`scripts/migrate_raw_qfq.py --verify-vendor`）。
  这是"宁可停下也不毁数据"的取舍——如果你更希望自动跟随 vendor，说一声我加一个显式开关。
- **R20-D-1（数据侧自愈的下一层）**：R20B 报的 B1（缓存看不懂"版本未推进的原位改写"，实测可返回
  偏差 −33% 的旧 ATR）当前**无仓内触发点**（所有写路径都推版本）。若将来加入"备份恢复/手工修数"
  功能，需要同时推版本或加校验；建议那时一并做。
- **R20-D-2（早期样本的因子质量）**：4 条 2005–2006 的"有因子但价格未跳"样本会在 qfq 里造出
  21~32% 的假跳变，全部落在在用回测窗口（2025-01-01 起）之外；若将来把回测窗口前移，需先清理。

## 七之八、R19 新增待决策点

- **R19-D-1（plateau 邻域宽度）**：现 ±20% 只给 1~2 个点 → 判据只能"低置信"；扩到 ±10/20/30%
  可得 4~6 点、σ 估计稳定；代价是探针 run 数翻倍（每探针 = 一次完整回测）。
- **R19-D-2（heat_cap 语义裁决）**：文档写"组合热上限"，实现只在准入时卡控（实测可到 4.15×cap）。
  ① 改文档口径（cap = 准入约束 + 事后告警，本轮已实现告警）；② 加部分卖出/风险回压机制（新功能）。
  **建议 ①**。
- **R19-D-3（L3 层 backlog 8 条）**：其中"heat_cap×无止损价 的告警文案与实测相反"与"缩放型 gate
  不落 gate_log"是如实性缺口，建议尽快修；其余（文档旗舰示例不可载入、position_risk/all_of 未注册、
  target_weight 无 Σw 校验、pending_exits 回测空转、停牌止损不可达、live 对账 qty 口径）随下次口径统一处理。

## 七之七、R18 新增待决策点

- **R18-D-1（DSR 阈值＝研究纪律的实质选择）**：现阈值 0.0 使 DSR 门恒真 → 平台**不做多重检验折扣**
  （论文口径 ≥0.95；按现量级多数实验会停在 inconclusive）。三条路：① 采纳论文口径 + 用邻域/探针 Δ
  提供跨试验方差；② 保持 0.0 但在报告里显式写明"未做折扣"（本轮已落证据标记）；③ 折中：把
  `attempt_index` 折进 t 门（Bonferroni/Holm 式），更易向使用者解释。**建议**：先 ②（已实现）+
  在下一个课题试 ③，若你要严格对齐论文再切 ①。
- **R18-D-2（E0002 卡 running）**：审计期间代理留下的未收口实验；平台**启动收割**会在下次服务启动
  时标为 failed（与日更漏跑同一次重启即可解决）。
- **重基线批次（三次修复累积）**：R15（创业板幅度）× R17（旧栈科创板策略腿）× R18（旧栈科创板基准腿）
  三处修复都会改变旧栈历史数字 → 建议一次性重跑批量回测 + 更新物化产物 + 给产物加"口径版本"标注。

## 七之六、R17 新增待决策点（含一条运维告警）

- **⚠ 日更已漏跑（建议立刻处理）**：库内最后一根 K 线为 **2026-09-23**，而 **2026-09-24 是交易日**、
  `daily_update` 最后一次 `run_date=2026-09-23`。所有出口都如实标注 09-23 截止（无标签失真），
  但**数据已落后 2 个交易日**。根因与 R5-D-6 同一条：**生产服务不在线 → 16:30 定时任务不会触发**。
  **建议**：重启服务（会自动补跑 + 装守卫）并确认 09-24/09-25 的数据落库。
- **R17-D-1（旧栈的规则保真度：补齐还是冻结）**：旧栈不仅缺"分品种最小申报"（R17 已补），
  还**完全不建模涨跌停/停牌/T+1**。两条路：① 继续补齐（旧栈数字会继续变化、需连续重基线）；
  ② 冻结并在 API/导出/manifest 上显式标注"不建模涨跌停/停牌/T+1，仅用于相对比较"。
  **建议**：先做 ②（零风险、立刻消除误读），当旧栈成为决策依据时再做 ①。
- **R17-D-2（旧栈 336 笔的重基线）**：本轮修复会使 5 只科创板标的（688802/688795/688498/
  688809/688111）的旧格子在**重跑后**变化，与 R15-D-1（创业板幅度）同属重基线范畴。

## 七之五、R16 新增待决策点

- **R16-D-1（2023-08-10「100+1」递增）**：非科创板买入现按 100 股整数倍向下取整 →
  系统性少买 ≤99 股（≈≤0.1% 仓位）。改它会让 2023-08-10 之后全部买入股数与 NAV 变化——
  **建议与 R15-D-1（创业板幅度修复后的重基线）一并做**，避免两次重述数字。
- **R16-D-2（科创板 ETF 申报单位）**：本轮按"股票 688xxx = 200 股"判定；科创板 ETF（588xxx）
  仍按 100 份（当前池内无 588 成交）。若将来交易该品种需再核对其申报单位。

## 七之三、R13 新增待决策点与流程改进

- **R13-D-1（短窗口的 calmar / 年化）**：60 根 +2%/日、仅一天 −0.05% 的买持腿 calmar 实测
  **267,830**、70 根一字板 `annual_return` 实测 **2.7e10**，会直达前端"卡玛比/年化"列。
  已证伪"这是浮点噪声"（由真实收益与真实回撤算出），故不属现有闸门口径；**建议**给短窗口的
  calmar/年化加**窗口长度**门槛（如 `n<20` 不发布），与 R9/R10 的闸门标定一并定。
- **R13-D-2（h2h 过拦截）**：任一腿退化时两腿 Sharpe 都被置 None，健康腿的合法值（0.9~1.2）
  在持久化报告里被隐藏——是"宁可少给"还是"各腿各判"，需要你定口径。
- **R13-D-3（profit_factor 的 999 哨兵）**：与导出 manifest 的"NULL=数据不足或不适用"冲突，
  建议统一为 NULL（会改存量导出文件的呈现）。
- **流程改进（本轮暴露）**：① 编辑失败后必须复核目标文件——R11A-F3 对 backfill 脚本的编辑
  当时失败，我没复核却在报告里写成"已修"，直到 R13B 才发现；② 修一个口径时先列出该口径的
  **全部消费者与兄弟字段**——T+1 漏了影子现金、年度块漏了同行的格子列，都是"同源只改一半"。

## 七之二、R12 新增待决策点

- **R12-D-1（实盘清单链部署前检查）**：F2/F3 修好后，建议**首次部署前**先跑一次
  `reconcile_daily_list` 对账，人工核对清单与真实持仓/可卖量一致；另需定：实盘止损基准
  用未复权实际成交价（现口径）还是复权价（会改止损价与浮盈口径）。
- **R12-D-2（导出权限模型）**：现在默认只导出调用者自己的实盘成交，admin 需显式 `live_all=true`
  才取全量。若你希望 admin 默认全量（或导出完全禁止非 admin），说一声我改默认。
- **R12-D-3（批次与日更的时间窗）**：批次现在会在运行期冻结写任务（决策 A3），
  因此 16:30 触发时若批次在跑，日更会顺延到批次结束（有 `daily_update_deferred` 留痕）。
  如果你希望反过来（批次避开 16:30 窗口启动），我可以加一个"16:00~17:00 拒启批次"的门。
