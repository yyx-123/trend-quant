# 历史龙头数据补齐（背景与数据来源）

> 执行日期：2026-09-23 起　｜　数据源：Tushare Pro　｜　状态：清单已产出，K 线灌库未开始

## 一、背景：为什么要补这批数据

现有标的池约 1000 只（股票为主、ETF 为辅），但它是**「现在视角」的龙头集合**，这带来两个缺口：

**缺口 ①：幸存者偏差。** 池子里的标的全是"现在还活着并且还很大"的公司。曾经是龙头、后来没落甚至退市的公司完全不在这批数据里 —— 例如
乐视网（2015 年市值千亿、2020 年退市）、康美药业、武钢股份、海通证券、中国重工，以及苏宁易购、河钢股份这类
"当年成交额排前 10、如今掉出视野"的公司。做历史回测时，**当年真正在涨的票有一部分根本不在样本里**，
策略的表现会被系统性高估。

**缺口 ②：行业覆盖偏窄。** 现在的标的集中在科技行业，其他行业虽然有一些但偏薄，
在行业轮动的年份会因为"池子里没票"而错过机会。

**因此要做的事**：找出**过去每一年规模靠前的股票和 ETF**，取并集，作为待补标的池。
这样既能把"当年的大票"补回来（解决缺口 ①），也能顺带把各行业的代表标的补进来（解决缺口 ②）。

## 二、为什么用 Tushare

项目当前的行情源 TickFlow 是**纯行情源**，解决不了这件事：

- 它的标的池只有**在市**标的（实测 5570 只股票 / 1715 只 ETF 全是在市），**不含退市股** ——
  `600005`（武钢股份，2017 退市）、`300372`（欣泰退，2017 退市）既不在标的池里，也取不到 K 线；
- 它**没有指数成分接口**，也没有股本/财务接口（`financials.*` 返回无权限）。

而 Tushare 恰好有三类**直接给出**的信息，一一对应上述缺口：

| 缺口 | Tushare 提供 |
| --- | --- |
| 当年哪些是大票 | `index_weight` 指数成分与权重（月度，**含已调出的退市股**） |
| 没落/退市的公司 | `stock_basic(list_status='D')` 退市股全名单 + `daily` 退市股全历史行情 |
| ETF 的池子与归属 | `fund_basic` 场内基金列表（**含已摘牌**，带业绩比较基准、投资类型、费率） |

**所有清单都取自 Tushare 的原始字段，不做二次推算。**

### 2.1 接口与积分门槛

需要一个 **5000 积分档**的临时账号（官方 500 元/年档）。关键接口门槛：

| 接口 | 用途 | 积分 |
| --- | --- | --- |
| `index_weight` | 指数成分与权重（月度） | 2000 |
| `stock_basic` | 股票基础信息；`list_status='D'` 给退市名单 | 2000 |
| `daily` | 股票日线（未复权，**含退市股**） | 基础积分 |
| `adj_factor` | 复权因子 | 2000 |
| `fund_basic` | 场内基金列表（含摘牌），带 benchmark / invest_type / 费率 | 2000 |
| `fund_daily` | ETF 日线行情（含成交额） | **5000** |
| `fund_share` | 基金份额 | 2000 |
| `trade_cal` | 交易日历 | 2000 |

注意 **`fund_daily` 要 5000 积分起**，只买 2000 档拿不到 ETF 行情。

### 2.2 用法约定

token 只通过环境变量注入（`TUSHARE_TOKEN` / `TUSHARE_HTTP_URL`），**脚本内不出现、不落盘、不入库、不进 git**，
沿用项目既有的 `scripts/tushare_common.py` 约定。`tushare` 是 `pyproject.toml` 的 optional extra，
需要时 `pip install tushare`（本机默认 PyPI 源会卡死，用清华源）。

## 三、股票侧：中证指数成分并集

### 3.1 为什么用指数成分，而不是自己算市值排名

中证的三条宽基指数，编制办法本身就把沪深市场**按市值切成了有次序的区间**，
所以直接取它们的成分就等于拿到了"当年市值排名前 1800"的分层结果：

| 指数 | 代码 | 覆盖市值排名 | 发布日 | 成分数 |
| --- | --- | --- | --- | --- |
| 沪深300 | 000300.SH | 1 – 300 | 2005-04-08 | 300 |
| 中证500 | 000905.SH | 301 – 800 | 2007-01-15 | 500 |
| 中证1000 | 000852.SH | 801 – 1800 | 2014-10-17 | 1000 |

（中证800 = 沪深300 + 中证500，是同一批票的另一个名字，单独取它是冗余的。）

### 3.2 取数

`index_weight` 是**月度**数据（每月最后一个交易日一期），来源是指数公司官网公开数据。

**分批策略**：单次返回上限约 7000 行，而中证500 一整年 12×500=6000 行、中证1000 一整年 12×1000=12000 行会超，
所以统一按**半年度窗口**拉取（脚本按 `index_code + 半年` 分片落盘，已存在的分片自动跳过，可断点续跑）。

最终拿到的快照期数：

| 指数 | 实际覆盖 | 快照期数 |
| --- | --- | --- |
| 沪深300 | 2005-04-29 ~ 2026-08-31 | 324 |
| 中证500 | 2007-01-31 ~ 2026-08-31 | 284 |
| 中证1000 | 2014-10-31 ~ 2026-08-31 | 143 |

早期年份的覆盖由指数发布日自然决定（2005-04 起有前 300，2007-01 起有前 800，2014-10 起有前 1800）。

### 3.3 分档规则

**每期快照各自判档，再跨期取并集**：

| 来源 | 判档 | 对应市值排名 |
| --- | --- | --- |
| 沪深300 全部成分 | `top300` | 1 – 300 |
| 中证500 全部成分 | `301_800` | 301 – 800 |
| 中证1000 按 `weight` 降序的**前 200 名** | `801_1000` | 801 – 1000 |
| 中证1000 其余 | `1001_1800` | 1001 – 1800 |

于是 **top1000 = top300 ∪ 301_800 ∪ 801_1000**，`1001_1800` 单独成一份。

中证1000 装的是市值 801–1800 名，它的前 200 名（按权重 ≈ 自由流通市值排序）就是 801–1000 名，
这样能把"市值前 1000"和"1000–1800"干净地分开，方便先只用前一份、不够再补后一份。

另有 `top1000_years` / `best_band` / `n_snap_top1000` / `delisted` 等列便于排序取舍。

## 四、ETF 侧：全量 ETF 清单与赛道去重

### 4.1 取数

- `fund_basic(market='E')` 取**全部场内基金**（`status='L'` + `'D'` 两次调用，后者含已摘牌），
  按名称含 `ETF` 过滤 → **1840 只**（1712 存续 + **128 已摘牌**）。
- `fund_daily(ts_code=…)` 逐只拉**全历史**日线（含 `amount` 成交额，单位**千元**）。
  单次上限 5000 行，只有极少数 2005 年前上市的老 ETF 会顶到上限，脚本会自动分两段重取。
  实际有历史行情的 **1720 只**。
- `fund_share(trade_date=…)` + `fund_daily(trade_date=…)` 各一次调用取全市场快照，用于估规模。

口径与换算：

- **当年日均成交额(亿元)** = Σ`amount`(千元) × 1000 ÷ 当年有行情的交易日数 ÷ 1e8
- 剔除当年成交月数 < 6 的标的（次新股、长期停牌），避免半截数据把自己抬进榜单
- 阈值：**2013–2026 年间至少一年日均成交额 ≥ 5000 万元** → 达标 **694 只**（排除货币型后 669 只）

### 4.2 主题去重（三级收敛）

`benchmark`（业绩比较基准）是各家指数公司的原始文案，**同一只指数常被写成多个字符串**，所以要去重。
`dedup_etf_themes.py` 分两级，互相独立：

| 级别 | 口径 | 结果 |
| --- | --- | --- |
| 原始 | 按 `benchmark` 文案分组，每组留成交额最大的一只 | 318 只 / 318 主题 |
| **Level A（机械）** | 剥离汇率前缀（`经估值汇率调整的` / `经人民币汇率调整的` / `同期`）、交易所全称（`上海证券交易所50成份` → `上证50`）、黄金写法、`中证小盘500` → `中证500` 等 | **289 只** |
| **Level B（赛道）** | 同一赛道内归并 | **175 只** |

Level A 合并前后对照（示例）：

| 归并后 | 只数 | 原本被当成不同主题的写法 |
| --- | --- | --- |
| 纳斯达克100 | 3 | `纳斯达克100` / `经人民币汇率调整的纳斯达克100` / `经估值汇率调整后的纳斯达克100` |
| 恒生科技 | 3 | `恒生科技` / `同期恒生科技` / `经人民币汇率调整的恒生科技` |
| 黄金 | 3 | `Au99.99合约` / `上海黄金交易所黄金现货实盘合约Au99.99价格` / … |
| 上海金集中定价 | 6 | `上海黄金交易所上海金集中定价合约` / `合约代码:SHAU)的午盘基准价格` / … |
| 中证500 | 2 | `中证小盘500` / `中证500` |
| 上证50 | 2 | `上海证券交易所50成份` / `上证50` |

Level B 的原则：**只有「同一暴露的不同版本」才合并**。主要合并：

| 赛道 | 合并前 → 后 | 说明 |
| --- | --- | --- |
| 跨境-港股医药 | 12 → 1 | 恒生生物科技 / 港股通创新药 / 恒生医疗保健 … |
| 红利策略 | 11 → 1 | 中证红利 / 上证红利 / 央企红利 / 红利低波 / 红利质量 / 高股息 |
| 半导体芯片 | 9 → 1 | 科创板芯片 / 半导体材料设备 / 国证半导体芯片 / 中证芯片产业 … |
| 跨境-港股科技 | 9 → 1 | 恒生科技 / 恒生互联网 / 港股通互联网 / 港股通信息技术 … |
| 跨境-港股红利 | 9 → 1 | 港股通央企红利 / 高股息 / 低波红利 … |
| 有色金属 | 8 → 1 | 有色 / 稀有金属 / 稀土 / 有色矿业 |

**宽基不合并**（沪深300 ≠ 中证500 ≠ 科创50）、**债券不合并**（不同期限与品种各有用途）、
**美股宽基不合并**（纳指 ≠ 标普 ≠ 道指）、**港股宽基不合并**（恒生 ≠ 恒生中国企业）。
所以 175 只里宽基 25 只、债券 25 只都完整保留，压缩主要发生在行业主题上。

Level B 是**主观的**，关键词表写在 `dedup_etf_themes.py` 顶部（`DOMESTIC` / `HK_BUCKETS` / `US_BUCKETS` / `BROAD`），
觉得哪一组并得太狠或不够狠，改关键词重跑即可（数据都在，秒出）。

### 4.3 结果

| 清单 | 只数 |
| --- | --- |
| `etf_candidates_final.csv` —— **最终清单**（赛道归并后每赛道一只） | **175** |
| `etf_candidates.csv` —— 去重前（每个 `benchmark` 主题一只，已排除货币型） | 318 |
| `etf_universe.csv` —— 全量主表（含未达标，便于换阈值重筛） | 1720 |

最终 175 只的大类分布：**宽基 25 / 行业主题 92 / 跨境 29 / 债券 25 / 商品 3 / 策略 1**。

### 4.4 已知局限

1. **规模列要谨慎用**。`fund_share.fd_share` 换算出的规模，实测交叉核对（与另一行情源的 `total_shares` 对比）：
   非货币 ETF 一致（偏差 1~8%，属日期口径差），但**货币型差约 100 倍**（Tushare 那边份额口径异常）。
   因此 `etf_universe.csv` 加了 `scale_reliable` 列，货币型标 `N` 且规模留空。
2. **`fund_nav.net_asset`（资产净值）对 ETF 是空的**，所以规模只能用"份额 × 收盘价"估算，不是官方口径。
3. **退市 ETF 里只有 5 只曾达标**，且峰值都很低（0.7~2.7 亿/日）。也就是说
   **ETF 领域基本不存在「当年很火、后来退市」的大标的** —— 与股票侧结论正好相反，
   ETF 侧的历史扩容空间主要来自**新发**，不是没落。
4. 主题归并依赖 `benchmark` 文案，**同名不同写法会分成两组**（如 `中证小盘500` 与 `中证500` 已在 Level A 处理，
   但仍有残留）。`benchmark` 原始值在 `etf_universe.csv` 里保留，可回溯。
5. 达标清单里混着**货币/黄金/商品类 ETF**（694 只里 42 只），它们成交额大但不是趋势标的，
   用 `invest_type` 一列即可过滤。
