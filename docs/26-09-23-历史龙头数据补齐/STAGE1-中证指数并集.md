# 阶段一：中证300 / 500 / 1000 历史成分并集（Tushare）

> 执行日期：2026-09-23　｜　数据源：Tushare Pro（临时账号，5000 积分档，镜像站 `tuaremax.top`）
> 脚本：`probe_tushare.py`（连通性探测）→ `fetch_tushare_index_members.py`（抓取 + 分类）
> **本阶段不拉任何 K 线，不写数据库任何表，只落 CSV。**

## 一、一句话结论

- 抓到三个指数的**全部历史成分快照**：沪深300 从 **2005-04-29** 起、中证500 从 **2007-01-31** 起、
  中证1000 从 **2014-10-31** 起（各自的发布当月月末），截至 2026-08-31，共 751 期快照。
- 分成两份互不重叠的清单：
  - **`universe_top1000.csv` — 2663 只**（曾经进过市值前 1000）
  - **`universe_1000_1800.csv` — 950 只**（只进过 1001–1800）
- 与 dev 库差分：top1000 里 **2068 只**、1000–1800 里 **923 只** 本地没有。
  **注意 dev 库标的比生产库少，这份差分必须在服务端重跑**（`diff_on_server.py`）。
- 附带拿到 **340 只退市股全名单**，其中 **235 只**出现在指数并集里 —— 乐视退、武钢股份、海通证券、
  康美药业、*ST凯乐、退金钰这一批「曾经是龙头、而今没落甚至退市」的票被完整捕获。

## 二、口径

### 2.1 三个指数的实际覆盖

| 指数 | 代码 | 发布日 | Tushare 成分数据起始 | 快照期数 |
| --- | --- | --- | --- | --- |
| 沪深300 | 000300.SH | 2005-04-08 | **2005-04-29** | 324 |
| 中证500 | 000905.SH | 2007-01-15 | **2007-01-31** | 284 |
| 中证1000 | 000852.SH | 2014-10-17 | **2014-10-31** | 143 |

`index_weight` 是**月度**数据（每月最后一个交易日一期）。用半年窗口分批抓（单次返回上限约 7000 行，
中证500 一整年 12×500=6000 行、中证1000 一整年 12×1000=12000 行会超，所以统一按半年度切）。

### 2.2 档位划分规则

**每期快照各自判档，再跨期取并集**：

| 来源 | 判为 |
| --- | --- |
| 沪深300 全部成分 | `top300` |
| 中证500 全部成分 | `301_800` |
| 中证1000 按 `weight` 降序的**前 200 名** | `801_1000` |
| 中证1000 其余 | `1001_1800` |

于是 **top1000 = top300 ∪ 301_800 ∪ 801_1000**。

中证1000 装的是市值 801–1800 名，它的前 200 名（按权重≈自由流通市值排序）就是 801–1000 名。

### 2.3 逐年实际入选只数（校验）

每年前 1000 名的并集**略多于 1000** 是正常的 —— 月度快照会捕捉到年内的成分变动：

| 年份 | 前1000并集 | 300 / 500 / 1000头 |
| --- | --- | --- |
| 2005 | 314 | 314 / — / — |
| 2007 | 863 | 337 / 550 / — |
| 2013 | 901 | 338 / 598 / — |
| 2014 | 1126 | 348 / 599 / 279 |
| 2018 | 1208 | 351 / 598 / 347 |
| 2023 | 1199 | 323 / 598 / 361 |
| 2026 | 1152 | 319 / 550 / 332 |

时间覆盖缺口（编制时间决定，已确认接受）：
- 2005-04 ~ 2007-01：只有沪深300 → 覆盖前 300
- 2007-01 ~ 2014-10：沪深300 + 中证500 → 覆盖前 800
- 2014-10 起：三只齐全 → 覆盖前 1000（`universe_1000_1800.csv` 覆盖到 1800）

## 五、已知局限（不影响使用，但要知道）

1. **801–1000 边界是模糊的**。中证1000 头部的边界靠权重排序近似，股价波动会让个股在边界两侧来回跳。
   2663 只里 **635 只**是只靠 `801_1000` 档进来的，其中 **89 只只出现过 1 期** —— 这 89 只大概率是边界抖动，
   严格说属于 1001 名开外。你的诉求是「有点误差无所谓」，所以我没有额外加过滤；要收紧的话，
   可以对 `801_1000` 档加一个「至少入档 N 期」的门槛。
2. **退市股只覆盖了「进过指数」的那部分**。340 只退市股里 235 只在并集里，剩下 **105 只**从没进过指数成分
   （小票），要的话得单独用 `stock_basic(list_status='D')` 全量并进来。
3. **2014-10 之前拿不到 801–1800 名**，这是中证1000 编制时间决定的，无法补。
4. `tushare_delisted.csv` 里有 2 条非标准代码（`TS0018.SH` / `T600018.SH`，上港集箱换股吸并的残留），
   是同一只票的两个历史代码，不会与正常代码冲突。

## 六、下一步（阶段二，K 线灌库）

**先不做**。等你确认清单后按这个顺序：

1. 在服务端跑 `diff_on_server.py`，用生产库重算增量
2. 逐标的判断数据来源：
   - **TickFlow 能取到完整历史的 → 用 TickFlow**（保持主口径一致）
   - **TickFlow 取不到的（主要是 2021 年前退市的）→ 用 Tushare** `daily` + `adj_factor`
3. 复权落库方式：写 `market_data_raw` + `ex_factors`（标 `provider`），qfq 由项目自己派生
   —— 别直接用 Tushare 的前复权价（项目有等差前复权把历史价格减穿零的事故记录）
4. **入池方式待定**：退市标的如果 `enabled=1`，日更会天天拉、天天失败；如果 `enabled=0`，
   回测又会把它们排除掉（幸存者偏差就白治了）。需要加一个第三态（例如 `delist_date` 列）。
