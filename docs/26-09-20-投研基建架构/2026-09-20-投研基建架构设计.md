## 0. 为什么现在必须做这件事（痛点复述）

两个痛点，都是结构性的，不是功能性的：

1. **单标的回测回答不了实盘问题。** 批量回测本质是"海量单标的各自回测 + 统计规律"，
   隐含资金无限假设。实盘是有限资金下的组合问题：信号每天几十上百个，买谁、买多少、
   槽位满了换不换、整体回撤怎么控制。单标的体系里"过滤器越加越差、随机入场也盈利"
   的观察（见组合构建调研附录 B）恰恰证明：过滤/排序/仓位这类问题的价值只能在
   资金约束下显现，现有工具在数学上测不到。
2. **AI 研究员没有可工作的环境。** 此前 research/ 下 7 项研究被全删，根因不是"乱"，
   而是**没有登记处**：每个 AI 各自实现止损/回测/指标，口径不一、结果不可比、
   无法审计。没有统一基建，AI 的每次研究都产出孤儿数据，删掉反而是正确的。
   要让 AI 从"实现者"升级为"研究员"，前提是它提出假设、获得反馈、沉淀结论的
   整条链路都有标准件——而且**置信度保障必须由平台流水线强制执行，不能靠提示词
   自觉**（见 §2.6）。（过往研究仅其背景有参考价值；研究本身不统一不规范，
   结论不作为任何架构或策略依据。）

## 1. 现状盘点（按目标分层映射）

### 1.1 数据层 —— 最完整，但有缺口

已有（质量较高）：

- TickFlow 唯一数据源，限流/配额管理（`src/data/provider_tickflow.py`）；
- **raw（不复权）为唯一真源，qfq 由 raw × 除权因子本地物化**（`src/core/adjustment.py`），
  除权处理 O(本地重算)、无历史回溯改写问题；
- `data_versions` 内容版本计数器：qfq 原位重写也能被缓存感知（`db.py:390`）；
- 指标缓存 `indicator_daily`/`trend_daily` 带 formula_version + data_version 双键，
  cache-first + live 回退（`src/data/indicator_store.py`）；
- PIT 意识已成体系：盘中合成 bar 不落库、周/月 provisional bar 有判定函数
  （`core/bars.py:176`）、滚动周/月趋势是 PIT 确定性函数（`core/rolling_bars.py`）；
- APScheduler 日更（16:30）+ 盘中 5 分钟快照 + 启动补偿。

缺口：

- **股票池不是时点动态的**：当前池 = 按"今天"的成交额/流动性筛选的 874 只
  （672 股票 + 201 ETF，另有方案 B 扩到 1160 的未执行计划）。回测历史时用的是
  今天的池子穿越回去——**幸存者偏差已存在但被回避**；
- 无退市股数据、无 ST 状态历史、无上市/退市日期
  （`instrument_metadata.start_date` 字段存在但无人消费）、无涨跌停价/停牌标记；
- 历史深度不均：874 只中 404 只数据仅从 2020 年开始，2015 股灾/2018 熊市两轮
  regime 只有百余只覆盖（数据源本身支持到 1993，拉深是回填工程不是采购问题）；
- `db.py` 2878 行 God class，行情/指标/策略/用户/回测结果揉在一起。

### 1.2 交易引擎层 —— 单标的引擎质量不错，但只是半个引擎

已有（`src/rule_backtest/`）：佣金万 0.854 双边、最低 5 元、印花税（卖出、仅股票）、
滑点 0.2%、整手 100、现金约束、跳空穿透止损按开盘价成交。round-trip 诊断
（R 倍数/MAE/MFE/假止损率）在同类自研系统里少见。

关键缺陷：

- **信号当日收盘计算、当日收盘价成交**——与用户实盘习惯（14 点左右看一眼、
  尾盘执行）近似吻合，但引擎层面从未显式建模"尾盘执行"这个约定，
  `BacktestExecutionConfig.signal_timing/fill_timing`（`models.py:23-24`）是
  **死字段，全代码库无人读取**；成交价与实盘实际成交价的差异也没有参数化吸收；
- 无涨跌停不可成交、无停牌显式建模（碰巧合理但无复牌处理）、T+1 仅隐式满足；
- **回测与实盘不是同一条代码路径**：止损逻辑有两份独立实现
  （`rule_backtest/state_values.py` vs `services/stop_loss.py`，口径刻意不同），
  靠注释维持一致；"实盘"= 看板信号 + 手工录入 `manual_trades` + 止损监控，
  是记账 + advisory，不是执行系统；
- 严格单标的、单仓位、全进全出，无组合概念。批量回测页不是组合回测——
  各标的独立 10 万本金跑完取中位数，无共享资金池、无并发持仓、无组合级回撤。

### 1.3 组合策略层 —— 完全缺失

没有任何组合层面的系统能力：无组合构建、无共享资金池回测、无组合级风控、
无策略库。`docs/26-09-14-组合构建调研/` 留存一份调研文档，**仅作背景参考，
其结论不作为架构或策略依据**；核心设计以本次架构讨论为准。

`position_strategies` 仓位管理功能（已于 2026-09-23 移除，commit 8ff23c4；盘点见 §2.7）。

### 1.4 投研层 —— 完全缺失

没有任何研究基建：无实验登记处、无标准化验证件、无策略血缘记录。

注意：**看板（subject-market）、单标的详情（market-view）、MCP 查询工具不属于
投研层，也不属于 L1-L4 的任何一层。** 它们是与研究栈并行的**展示/应用分支**：
消费数据层的数据，做加工（趋势值、强度等）并展示（前端页面、MCP 透出）。
详见 §2.1。

## 2. 目标架构

### 2.1 总体形态：执行面严格分层 + 数据面共享门面

```
┌─────────────────────────────────────────────────────────────┐
│ L4 投研层：实验台账 / 研究编排 / 纪律流水线 / AI·人接口       │
└──────────────┬───────────────────────────────┬──────────────┘
               │ 执行面：只能调 L3              │ 数据面
               ▼                               │
┌─────────────────────────────────────────┐   │
│ L3 组合策略层：策略（插槽配置）/ 组合回测 │   │
│ / 策略库 / 实盘运行器 / 报告与指标        │   │
└──────────────┬──────────────────────────┬─┘
               │ 执行面：只能调 L2          │ 数据面
               ▼                          │ │
┌─────────────────────────────────────┐  │ │
│ L2 交易引擎层（纯执行）：订单/成交/   │  │ │
│ 持仓/账户 + A 股规则                  │  │ │
└──────────────┬──────────────────────┘  │ │
               │                          ▼ ▼
               │        ┌──────────────────────────────────────┐
               └───────►│ L1.5 数据门面层（全系统唯一数据咽喉） │
                        │ as-of 强制 / 可交易性标注（涨跌停·停  │
                        │ 牌）/ 面板读取 / 生产指标直取 / 元数据 │
                        └──────────────┬───────────────────────┘
                                       ▼
                        ┌──────────────────────────────────────┐
                        │ L1 数据层：K线(raw真源+qfq物化)/元数据 │
                        │ /生产指标缓存/日更调度/data_version    │
                        └──────────────────────────────────────┘

（并行分支，不属于 L1-L4）
┌─────────────────────────────────────────────────────────────┐
│ 展示/应用分支：看板、单标的详情、MCP 查询、手工交易录入       │
│ 现状：直接消费 L1 数据 + core 加工做展示；后续可迁 L1.5       │
└─────────────────────────────────────────────────────────────┘
```

**依赖铁律（两条，替代 v3 的单链规则）：**

1. **执行面严格逐层**：L4→L3→L2，每层只能调直接下一层，禁止跨层；
2. **数据面共享门面**：L2、L3、L4 的一切数据需求都只经 L1.5，**任何层不得绕过
   L1.5 直连 L1**。L1.5 是全系统唯一数据咽喉——as-of 卡控、可交易性语义只在这
   一处实现，上层物理上不可能绕过。L1.5 永不回调上层。

两条规则合起来的含义：要"交易"就必须走完 L4→L3→L2 的执行链；只要"数据"就
直读 L1.5（例如未来的因子研究：只要数据不要引擎，L4 读 L1.5 即可，不必惊动
L3/L2——这正是门面独立成层的正当性来源）。

其他形态要点：

- **分层按"管理什么对象"切**：L3 的对象是策略（定义、回测、注册、部署），
  L4 的对象是**课题与实验**（课题=研究问题，必选归属、强制结论；实验=对问题
  的一次检验。AI 工作流固定为"先提课题、再设计实验"，见 §2.6）。人和 AI 是
  同角色的两种客户端，共用服务面。
- **实盘运行器挂在 L3，与组合回测器消费同一个策略对象。** 无券商接口
  （QMT/ptrade 暂不引入），"回测实盘同路径"的现实形态：策略对象 + 引擎代码
  同时驱动（a）历史模拟和（b）每个交易日 14:00 前后产出"目标持仓 + 应买应卖
  清单"；人工下单后用 manual_trades 录入、与目标清单对账。差异（实际成交价 vs
  清单基准价、未执行）本身就是实盘滑点的度量，反过来标定引擎的尾盘执行滑点参数。
- **展示/应用分支维持现状，不塞进 L1-L4。** 它是独立产品表面，与研究栈各自
  演化；后续可迁到 L1.5 取数（顺带获得统一 PIT 语义），但不强制、不阻塞。

### 2.2 L1 数据层：只对 L1.5 承诺三类东西

1. **标准面板数据读取**：`get_panel(symbols, start, end, fields, adjust, as_of)`；
   批量载入内存面板（numpy/pandas）。现有 `load_market_data_many` 是雏形。
2. **元数据**：交易日历（已有）、上市/退市日期、ST 状态历史、成交额/市值历史、
   行业分类（已有三级类目）、指数成分历史（若能拿到）。
3. **生产指标缓存**（维持现状）：趋势值、ATR、MACD 等少数参数稳定的生产指标，
   继续走 `indicator_daily` + data_version 键控的既有机制。

**划界（见 §3.3）：研究用因子/信号不进入数据层。**
数据深化（年度行业龙头动态池、退市股、历史拉深）是已定方向的独立线，见 §3.5。

**举例**：510500.SS 的日 K 生命周期——TickFlow 拉原始行情落
`market_data_raw`（只增不改）；分红除权后因子落 `ex_factors`，
`market_data_qfq` 全段原位重算、`data_versions` +1；日更后该标的的
指标缓存因 data_version 变化被重建。上游任何时候读到的都是口径一致的
数据，且靠 data_version 能感知"日期没变但价格口径变了"。

### 2.3 L1.5 数据门面层：唯一数据咽喉

对上的唯一数据入口。职责（也只这些）：

- **as-of 强制**：请求方声明决策时刻 t，门面物理上不返回 t 之后的信息——
  PIT 卡控从"消费方自觉"变成"门面强制"；
- **可交易性标注**：逐日逐标的给出 停牌（无 bar）/涨停/跌停 标记。涨跌停价由
  **除权基准修正后**的前收盘价按板块规则推导（除权日须用 ex_factors 修正
  基准价，否则涨停判定算错——主板 ±10%、创业板/科创 ±20%、ST ±5%——
  ST 状态历史需要元数据支持，见 §3.5；推导细节见详设 §3.2）；
- **面板读取**（K 线 + 生产指标直取）、**元数据**（日历、行业、上市日期、
  股票池成员）；
- 数据请求留痕（谁在什么时候以什么 as-of 取了什么——实验血缘的一部分）。

**举例**：组合回测器跑 2024-03-15 的日循环，调
`get_panel(symbols=[约800只], fields=[open,close], adjust=qfq,
as_of=2024-03-15, mode=historical)`——门面只返回 ≤3-15 的数据（之后
一行都没有）；同次调用返回可交易性标注：某创业板标的当日涨停价 =
昨收×1.20 且收盘价已顶格 → `is_limit_up=True`，引擎将据此拒买。
本次调用留痕：调用层=L3、as_of=2024-03-15、data_version=418——
实验血缘里"它当时看到的是哪一版数据"由此而来。

### 2.4 L2 交易引擎层（纯执行）：一个引擎，A 股规则完备

职责边界：只懂"给我订单，我按 A 股规则撮合并记账"。数据需求经 L1.5；
不懂策略、不懂选股、不懂研究。

**核心模型（字段草样，对照 vnpy / QuantConnect LEAN / backtrader 设计）**：

```
Order（订单=意图；决策日与成交日分列，尾盘口径的审计需要）：
  id, run_id(回测/实盘运行), decision_date, target_fill_date,
  symbol, side(buy|sell),
  intent: quantity | target_quantity | target_weight,   # 目标语义便于调仓
  source: signal|stop|rotation|rebalance,               # 哪个决策产生的
  status: pending|filled|rejected|unfilled, created_at

Fill（成交=事实，一笔订单零到一笔成交；费用分列）：
  order_id, symbol, fill_date,
  base_price(基准价=T收盘), slippage_base, slippage_tail(尾盘执行滑点),
  fill_price, quantity,
  commission(含最低5元规则), stamp_tax, fee_total,
  cash_after
  —— 未成交也落账：unfilled_reason ∈
     {limit_up, limit_down, suspended, t1_block, insufficient_cash, lot_rounding}
     （"错过的交易"本身是研究素材；现有引擎 skipped_buys 已有此意识）

Position（T+1 一等表达：可卖数量是显式字段，参照 vnpy yd_volume）：
  symbol, quantity, sellable_quantity(昨仓),
  avg_cost(含买入费用), entry_date, entry_price(实际买入价=止损基准),
  风控状态: stop_price, highest_since_buy(吊灯), atr_at_entry

Account：
  cash, positions_value, equity,
  派生日志: daily_nav, portfolio_heat(所有持仓现价→止损的潜在亏损合计)
```

设计要点：

- **T+1 显式**：当日买入计入 quantity 但不计入 sellable_quantity，卖出校验
  sellable——不再靠"循环顺序碰巧对"；
- **涨跌停/停牌**：订单撮合时查 L1.5 的可交易性标注，不可成交记 unfilled_reason；
- **费用规则**（沿用现有模型）：印花税卖出收（股票 0.05%、ETF 免）、佣金万
  0.854 双边最低 5 元、基础滑点 0.2% 双边不利方向、整手 100（买入对齐、卖出
  全清）、现金约束；**规则参数化预留**（market profile，首版 cn_stock）见
  详设 §4.2.1；
- **成交口径（决策 1，已定）**：信号以 T 日收盘数据计算（≈14:00 尾盘状态），
  成交基准价 = T 日收盘价，叠加**尾盘执行滑点**参数吸收实盘价差；残余前视
  由该滑点吸收，并由实盘对账持续标定；
- **收编止损双实现**：`state_values.py`（回测）与 `stop_loss.py`（实盘）合并为
  L2 持仓风控原语，**以实际买入价为基准、ATR 含当根**（决策 6，已定；与现行
  实盘侧一致，回测侧向实盘侧对齐）；
- **回测与实盘同一条代码路径**：组合回测运行器与实盘运行器都驱动同一个
  引擎实例族，差异只在数据源是历史面板还是当日数据。

**举例**：一笔买入的完整生命周期——决策日 2024-03-15，信号模块产出
510500 买入候选，sizing 定量 4600 股，引擎校验（未停牌/未涨停/现金够/
整手）→ 成交：基准价 5.82（当日收盘）×(1+0.002 基础滑点+0.001 尾盘
滑点）=5.837，佣金 5.00 元（万 0.854 不足 5 元按最低 5 元）、印花税 0
（买入不收）；当日 quantity=4600 但 sellable=0（T+1）。同日另一只
159915 收盘涨停 → 订单不进 fills，进 `engine_unfilled`（reason=
limit_up）——成为"错过的交易"研究素材。

### 2.5 L3 组合策略层：策略 = 带类型插槽的配置

**策略不是一坨代码，而是配置。** 每个插槽是可替换模块，接口固定、独立版本化：

| 插槽 | 职责 | 示例模块 | 现状 | LEAN 对照 |
|---|---|---|---|---|
| `universe` 标的池 | 哪些标的有资格被交易 | 三级类目过滤、流动性过滤、（数据线）年度龙头动态池 | 有雏形 | Universe Selection |
| `signal` 信号 | 逐标的产出入场/离场事件流 | MACD 金叉/死叉、趋势值穿越 | rule_backtest 条件引擎可迁移 | Alpha Model |
| `rank` 排序 | 候选信号的资金竞争排序 | 信号新鲜度、ER、随机（合法默认！） | **缺失** | （隐含于 Alpha 置信度+组合构建，此处显式化） |
| `sizing` 仓位 | 单笔买多少 | 等风险（risk_budget 数学迁入）、固定比例 | 待打捞 | Portfolio Construction |
| `portfolio_risk` 组合风控 | 总风险封顶 | 槽位数上限、组合热上限、行业集中度、breadth 闸门 | **缺失** | Risk Management（组合级） |
| `position_risk` 持仓风控 | 单持仓离场 | 硬止损、吊灯、棘轮吊灯、时间止损 | 有（双实现待收编） | Risk Management（持仓级） |
| `execution` 执行 | 成交时点与调仓/轮换策略 | T 日尾盘成交、事件驱动调仓、滞后带宽轮换 | 口径已定（决策 1） | Execution |

**插槽清单的外部验证**（对照 QuantConnect LEAN Algorithm Framework / qlib /
backtrader）：LEAN 的五模块插槽化（Universe→Alpha→PortfolioConstruction→
RiskManagement→Execution）与七插槽一一对应；多出的两个有显式理由——`rank`
在小资金、事件型信号、槽位制下值得一等存在（qlib 的 TopkDropoutStrategy 同样
证明"排序+缓冲带宽"是一等概念）；风控拆二因为"单票怎么死"与"组合怎么活"是
两类对象、两条研究线。backtrader 的单 Strategy 巨石（一切塞 next()）是反例。
另：调仓/轮换的缓冲规则（buffer、跌出前 2N 才换）归属 `execution` 槽。

插槽设计的两条纪律：

1. **每个插槽都必须有"无脑默认实现"，且它是一等公民。** 架构立场：未经对照
   实验证实的机制不值钱——每个旋钮都先和"不动脑子的版本"比，让实验去证明
   它值多少钱。benchmark 思想下沉到插槽级。
2. **实验 = 一个模板 + 恰好一个插槽的 diff。** 台账存 diff 不存策略副本；
   AI 生成实验 = 在合法插槽里换已注册模块（含参数域校验），灵活但跑不出格。

组合回测器（L3 核心引擎）的日循环骨架（尾盘口径）：

```
每个交易日 t：
  1. 持仓风控评估：逐持仓检查止损/离场（盘中触及止损价按止损价成交，跳空按开盘）
  2. 信号扫描：universe 内逐标的算事件（经 L1.5 取截至 t 收盘的数据）
  3. 排序与筛选：rank 槽排序候选 → portfolio_risk 槽卡控
     （槽位/热上限/集中度/breadth 闸门）→ sizing 槽定量
  4. 当日尾盘成交：经 L2 下单，成交价 = t 收盘价 × (1 ± (基础滑点+尾盘滑点))，
     涨跌停/停牌/T+1 卡控
```

**策略库**：入库策略版本化、不可变，完整血缘——策略版本、各插槽模块版本、
data_version、引擎版本、代码 git hash、产出它的实验 id。benchmark 策略首批入库：
买入并持有沪深300ETF、universe 等权月度再平衡、随机入场+相同止损（猴子基准）、
候选中随机选择（检验排序槽的价值）。

**举例**：基准策略 v1（当前实盘打法的 1:1 复刻）就是一份配置——
`universe: 流动性过滤`、`signal: macd_cross@1`、`rank: by_freshness@1`、
`sizing: equal_risk@1(0.75%)`、`portfolio_risk: [slot_limit(10),
heat_cap(6%), concentration_cap(2)]`、`position_risk: chandelier@1(2.5)`、
`execution: tail_session@1`。把任何一个槽换成别的已注册模块就是一个
改进型实验；七个槽全换成 none 就是空白基准 `blank-base@1`（新策略
实验的 diff 起点）。

### 2.6 L4 投研层：对象 = 课题 + 实验，纪律靠流水线强制

**两级对象模型（决策 18）**：课题（一个研究问题，实验的**必选归属**，强制
终态结论，上看板全员可读）→ 实验（对该问题的一次检验）。AI 的工作流固定
为**先提课题、再设计课题下的实验**——研究从问题出发，不允许"无课题的
漫游式实验"。课题结论有量化纪律（平台生成摘要 + 四档分级，决策 20）。
详见详设 §6.4.1 / §6.4.2。

**实验 = 固定骨架（认识论）+ 可插拔评估方法（取证手段）**（决策 15，范式
重设计）。固定骨架对所有实验强制：假设先行、对照显式声明、单变量、结论
取相对对照的差值、verdict 平台生成 + append-only + 尝试计数。评估方法是
实验的必填插槽，取已注册评估模块（过自动测试门，见详设 §6.2.2），首批四个：`portfolio_backtest`
（基准策略 + 插槽 diff → L3 回测，机制类问题）、`event_study`（事件前瞻
收益，信号有没有料）、`bucket_analysis`（截面分桶，特征有没有排序力）、
`distribution`（池化分布，参数标定）。**新增研究形态 = 新增评估模块，
不是新增实验类别**；被删研究的全部形态（组合机制/相位迁移/分桶/分布
标定）由此各归其位。详见详设 §6.1。

**没有晋升门**：假设 → L3 回测不设门槛（回测便宜，随便跑）。唯一的"门"在
**策略库入库**：能被实盘部署的版本化策略必须有完整实验血缘（由哪个实验产出、
相对基准的 deltas、各版本锚点齐全）——回测随便跑，入库要血缘。

**举例**：课题 T07「MA20 交叉策略是否值得做」→ 实验 E201
（event_study：MA20 金叉事件前瞻收益 vs 无条件分布——先快筛"有没有料"，
confirmed）→ E202（portfolio_backtest 创建型：blank-base + 七槽全填
signal=ma_cross@1，vs benchmark 阶梯——再验证"赚不赚钱"，rejected：
信号太密、换手成本吃掉 edge）→ 课题结论"信号含信息但策略化失败"，T07
concluded。E201/E202 完整报告与 spec 落在 `research/topics/T07*/` 下，
后来的 AI 可读报告、可复现、可在此基础上提修正实验（parent=E202）。

实验台账 schema（概念）：

```
experiment:
  id, title, created_by(human|ai), owner_session, created_at
  base: strategy_version_id          # 基准策略（不可变引用）
  diff: [{slot, from: module@ver, to: module@ver, params}]
  hypothesis: text                   # 预期方向与机制，先写故事后看数
  execution: {backtest_run_ids, data_version, engine_version}
  result: {metrics, deltas_vs_base, regime_breakdown, plateau_check}
  verdict: confirmed | rejected | inconclusive
  attempt_index: int                 # 该策略线上的第 N 次实验（显著性折扣依据）
  holdout_touched: bool
```

**台账的定位：全员可读、只增不改的经验资产（不是"成功实验的陈列柜"）。**
三条原则：

1. **失败与成功同等入表。** 每一次实验都有价值：confirmed 提供可复用的机制，
   rejected 提供"此路不通"的负结果先验，inconclusive 标记边界。只记成功的
   台账会诱导重复踩坑——一个假设被否掉，后来的 AI/会话必须能查到它被否过、
   为什么被否。verdict 三态本就为此设计，不存在"失败的实验不入表"；
2. **全员只读开放。** 任何人、任何 AI、任何会话都可以读台账全量（含他人失败
   的实验）——它是沉淀下来的经验教训资产和看板。隔离机制（§2.6）隔离的是
   **运行中间态与写入命名空间**，结果永远公开；
3. **只增不改（append-only）。** 实验记录不可篡改：结果与 verdict 由平台流水
   线写入，AI 只能写 reasoning；修正靠补充新记录或发起新实验，历史永不改写。
   这是台账一切下游功能（重复检测、显著性折扣、血缘审计）可信的前提。

**纪律不靠提示词，靠流水线（平台强制执行）**——这正是"投研基建/平台"的意义
所在：每个实验结束后拿到的不只是结果，而是过了同一套纪律的、置信度可比的
结果。机制清单：

1. **schema 强制**：hypothesis 为空、diff 跨多个插槽（未标记 compound）、base
   是可变引用的实验——**创建不了**。门槛设在入口，不靠事后检查；
2. **verdict 平台自动生成**：回测完成 → 平台自动计算 deltas vs base、
   regime 拆分（基准 SMA200 上/下、breadth 分段）、换手与成本明细——不是
   AI 自报的；
3. **参数高原自动补跑**：diff 中改动的数值参数，平台自动在邻域（如 ±20%）
   补跑，verdict 附"高原/孤峰"判定——孤峰即过拟合，无需谁记得去查；
4. **holdout 工程化**：数据窗口分 sample/holdout；回测 API 默认只放 sample；
   holdout 回测需显式放行 + 自动计数 + 每策略线限额，holdout_touched 自动记录；
5. **attempt_index 平台维护**：verdict 自动带"第 N 次尝试"的显著性折扣提示
   （尝试越多，显著性标准越严，参照 Deflated Sharpe 的思想）；
6. **重复实验检测**：新实验 diff 与台账已有实验相似时告警，防 AI 重复发现；
7. **判定规则平台持有**：verdict 建议（confirmed/rejected/inconclusive）由平台
   按阈值化规则给出；AI 可以写 reasoning，不能改判定规则；
8. **多插槽变更的处置（三级）**：默认一个实验只动一个插槽。需要动多个时——
   **优先拆成串行实验链**（先跑改 A 槽的实验，在结果之上再跑改 B 槽的实验：
   每步可归因，台账留下一串有血缘的实验而非一个黑箱）；确有交互效应
   （A 的结论依赖 B 的取值）才用显式标记 compound 的复合实验，结论置信度
   降档；若两个槽**总是**联动，说明插槽边界划错了，该重划边界而不是反复
   做复合实验。

**AI 接入形态与实验隔离（决策 4）**：接入通道不绑定 MCP（MCP、CLI、Python API
皆可为通道，服务层唯一，薄通道厚服务）。隔离机制：

1. **实验是声明式的**：AI 只能组合已注册模块 + 合法参数域，无任意代码执行；
2. **攻击面 = L3 服务面 + L1.5 只读门面**：能做的操作被枚举干净，且都过
   as-of 卡控；
3. **有界并发池 + 写入按 owner_session 归属**：不锁单运行——回测运行本质是
   只读取数 + 写自己命名空间，冲突面很小，按机器资源配 2~4 个并发位即可
   （防的是内存/CPU 挤爆，不是防冲突）。并发安全靠三件事：经 L1.5 只读取数
   且按 data_version 锚定（日更/指标重建改写数据影响不到已锚定的运行）；
   写入 append-only 且按 run/会话命名空间；运行间无共享可变状态。中间态
   互不可见；**最终记录（含失败实验）全员只读开放**，见上文台账定位；
4. **新模块进注册表过自动测试门**：唯一需要写代码的环节，隔离在实验
   循环之外；平台自动跑契约/确定性/前缀稳定性（前视探针）测试，人保留
   抽检与下架权（决策 16）——不设人审必经门；

**因子挖掘（决策 12，明确推迟）**：散户的及格线问题在仓位管理、止损、组合
风控，因子挖掘排在这些之后。本版架构只为其预留位置（L4 的一个研究方向：
因子条目登记 + 表达式 DSL + 经 L1.5 直读数据的向量化评估），**不排入实施
主线**，有需要时再启动。

### 2.8 各层是新建还是迭代？对存量的影响

| 层 | 包 | 性质 | 对存量的影响 |
|---|---|---|---|
| L1 | `src/data/`（现有） | **迭代**：新增面板批量读取与元数据字段；raw 真源/qfq 物化/指标缓存/日更调度全部保留不动 | 无破坏性变更；旧分支继续直读 L1 |
| L1.5 | `src/gateway/` | **新建**：薄门面，不复制数据，只在读取之上加装 as-of/可交易性/留痕 | 纯新增；展示分支是否迁入后议，不强制 |
| L2 | `src/engine/` | **新建**：组合级纯执行引擎 | 旧 rule_backtest 引擎保留并行；止损"收编"= 新栈统一实现，旧代码不动；费用常量打捞共享 |
| L3 | `src/portfolio/` | **新建** | 无存量冲突；仓位管理功能删除是唯一存量删除项（risk_budget 数学打捞后进 L3） |
| L4 | `src/research/` + `research/topics/` | **新建** | 无存量冲突；台账新表，不动旧表 |

一句话：**L1 迭代，L1.5/L2/L3/L4 新建；存量唯一被删除的是仓位管理功能，
其余旧功能（单标的/批量回测、看板、手工交易、MCP）原样保留继续运行**——
新栈与旧分支并行，互不阻塞、互不改写。

## 3. 批判性讨论：对初始提案的修正与定论

### 3.1 插槽清单：两个伪需求，一个真遗漏

初始清单：标的池 + 信号 + 权重 + 风控(止损/止盈) + 仓位 + 执行。问题：

- **"权重模块"和"仓位模块"是同一个东西**（决定每笔买多少），合并为 `sizing`；
- **"风控"是两类对象**：持仓级（单票怎么死）与组合级（整体怎么活），拆成
  `position_risk` 与 `portfolio_risk`；
- **真遗漏是 `rank` 排序槽**：组合层的本质问题是"有限资金下 N 个候选抢 M 个
  槽位"，排序是裁决机制。架构立场：未经对照实验证实的排序不值钱，所以默认
  实现可以很蠢（新鲜度甚至随机），让实验去证明价值。
- 外部验证见 §2.5（LEAN 五模块对照）。

### 3.2 成交口径：定为 T 日尾盘/收盘 + 尾盘执行滑点（决策 1，已定）

- 用户实盘习惯：每日 14 点左右看信号、尾盘执行，不喜欢开盘操作；成交价与
  收盘价的差异可接受，由引擎**尾盘执行滑点**参数模拟；
- 残余前视（用 15:00 收盘价近似 14:00 决策）由加码滑点吸收，并由实盘运行器
  每日 14:00 真实出信号 + 对账持续标定；
- 涨跌停/停牌卡控保留（T 日涨停不可买、跌停不可卖）；
- **意外收益**：旧单标的引擎本来就是 T 收盘成交，两分支口径一致、数字可比。
- 引擎相应改动：`signal_timing/fill_timing` 死字段重建为显式"尾盘执行模型"。

### 3.3 "数据层预计算指标"要划界：生产指标留，研究因子出

现有 indicator_daily 那套（raw 真源 + data_version + 全量重建）对十几个参数
稳定的生产指标是对的；研究用的成百上千个因子（参数各异、朝生暮死）绝不能进
数据层。划界：**数据层只承诺 K 线、元数据、少数生产指标；研究计算（未来含
因子）经 L1.5 取数后在投研侧完成，缓存按 (data_version, 表达式) 键控，算完
即弃也可。**（因子挖掘本身已推迟，此划界是为未来预留的原则。）

### 3.4 实验台账要先于组合回测器落地

**先定台账 schema，再建组合回测器。** research/ 七项研究被全删的根因是没有
登记处、统一口径与血缘；没有台账的基建等于给未来再制造一次"全删"。规矩：
任何回测运行必须挂在实验 id 下才允许落库（ad-hoc 探索可跑，但结果不登记、
不引用、不比较）。

### 3.5 数据深化：方向已定为"年度行业龙头动态池"（决策 2，已定）

- 目标池：从 2015 年（或更早）起，每一年的行业龙头都纳入并维护日 K——含
  "当年是龙头、现在不是"与"已退市"的股票。实质是时点动态股票池的用户版
  定义，幸存者偏差由构造方式直接消除；
- 待解子问题（数据线启动时再定，不阻塞主线）：①"龙头"判定规则（历史市值
  数据 TickFlow 能否提供待验证；历史成交额可从日 K 量×价推导，现成）；
  ②TickFlow 退市股数据能力（拿不到则降级 + 报告标注偏差）；
- 主线不等：先在"现有池 + 2020 至今"跑（2021 结构牛、2022–2024 回撤、
  2024 底反转，已含一轮完整牛熊），数据线成熟后窗口再向 2015 延伸。

### 3.6 反过度设计：平台 = 接口纪律，不是基础设施

- 继续 SQLite 单库（千万行级无压力），不引入 DuckDB/Parquet，除非性能实测
  过不去（到时迁 L1.5 的读取实现，接口不变）；
- 不拆服务、不微服务；模块 = Python 包 + Protocol 接口；
- `db.py` God class 拆分顺手做，不单独立项；
- **实盘运行器做薄版**（决策 3，已定）：每日 14:00 前后清单 + manual_trades
  对账；现有盘中 5 分钟快照 + 合成 bar 基建直接支撑 14:00 信号产出；
- 路线以**"基准策略 v1 的实盘对照"为第一个里程碑**倒排：v1 = 当前实盘打法
  1:1 复刻（决策 5，已定）；调研文档 §6 五条即时建议作为第一个正式实验的
  diff（实验素材，不代表采信其结论）。

## 5. 决策记录与遗留问题

### 已定论（2026-09-20 与用户讨论 + 两轮审查）

1. **成交口径**：T 日尾盘/收盘；信号用 T 收盘数据计算（≈14:00 状态），成交
   基准价 = T 收盘价，尾盘执行滑点参数吸收实盘价差；涨跌停 T 日卡控。（→ §3.2）
2. **数据范围**：年度行业龙头动态池（2015 或更早起，含退市/掉队者）；龙头
   判定规则与退市股数据能力是遗留子问题。（→ §3.5）
3. **实盘形态**：系统出清单、手工下单、录入对账；不引入 QMT/ptrade；实盘
   运行器薄版。（→ §3.6）
4. **AI 接入与隔离**：通道不绑定 MCP；声明式实验 + 服务面 + 只读锚定 + 有界
   并发池（2~4 并发位，多会话可并行研究）+ 会话归属 + 新模块过自动测试门
   （决策 16）。（→ §2.6）
5. **基准策略 v1** = 当前实盘打法 1:1 复刻；调研五条建议为第一个实验 diff 素材。（→ §3.6）
6. **止损收编口径**：实际买入价基准、ATR 含当根（回测侧向实盘侧对齐）。（→ §2.4）
7. **分层铁律**：执行面严格 L4→L3→L2；数据面共享 L1.5 唯一门面，禁止绕过
   直连 L1。（→ §2.1）
8. **无晋升门**：假设→L3 回测不设门槛；唯一门在策略库入库（必须实验血缘）。（→ §2.6）
9. **展示/应用分支不属于 L1-L4**：看板、单标的、MCP 查询、手工交易录入并行
   演化，维持现状。（→ §1.4、§2.1）
10. **L1.5 数据门面独立成层**：L2 不兼数据门面、回归纯执行；as-of 与可交易性
    语义全系统只在 L1.5 实现一处。（→ §2.3）
11. **实验纪律平台流水线强制**：schema 入口卡控、verdict 自动生成、参数高原
    自动补跑、holdout 工程化、尝试计数与显著性折扣、重复检测、判定规则平台
    持有。（→ §2.6）
12. **工业化因子生产推迟**（表达式 DSL、因子库、相关性聚类）；轻量评估
    （event_study/bucket_analysis/distribution）作为首批评估模块不推迟。
    （→ §2.6、§4）
13. **仓位管理功能实施首项移除**（risk_budget 数学打捞进 sizing 槽；手工交易
    页试算器另行处置）——**已于 2026-09-23 完成（commit 8ff23c4）**。（→ §2.7）
14. **台账是全员可读、只增不改的经验资产**：失败/成功/无结论实验同等入表；
    任何人/AI/会话只读开放（含他人失败记录）；append-only，结果与 verdict
    由平台流水线写入，AI 只能写 reasoning。（→ §2.6）
15. **实验范式 = 固定骨架 + 可插拔评估方法**：骨架（假设先行/对照/单变量/
    差值结论/平台 verdict）对所有实验强制；评估方法取注册模块，首批
    backtest/event_study/bucket/distribution 四个；新增研究形态 = 新增评估
    模块（过自动测试门，见决策 16），不是新增实验类别。（→ §2.6，详设 §6.1）
16. **模块治理不设人审必经门**：数据越界前视归 L1.5（as-of 强制）；新模块
    保存自由（draft），过自动测试门（契约/确定性/前缀稳定性前视探针）即
    可执行；人保留抽检与下架权；DSL 表达式免测。（→ 详设 §6.2.2）
17. **课题文件夹制**：`research/topics/<id>/` 承载课题/实验报告 + 复现清单
    （spec、模块版本、data_version、git hash）；看板（DB）是查询面，文件夹
    是阅读/审计/复现面，平台同源生成。课题为实验必选归属。（→ 详设 §6.4.1）
18. **L4 两级对象模型**：课题（研究问题，实验的必选归属、强制终态结论、
    上看板）→ 实验（一次检验）；AI 工作流 = 先提课题、再设计实验。
    （→ §2.6，详设 §6.4.1）
19. **一期/二期边界**：一期 = 阶段 0–5（基建整个建完，含 walk-forward、
    Sortino 推断、head_to_head、recompute campaign、台账看板 UI 等全部
    机制件）；二期 = 明确暂时不做的项（因子挖掘工业化、加仓 lot 账/网格、
    数据线、meta-portfolio、组合优化 sizing、冲击成本模型、purged CV、
    分布式实验）；做空永不做。逐项判断见 `2026-09-23-后续TODO.md`。
20. **课题结论量化纪律**：课题 concluded 前平台自动生成量化摘要（verdict
    计数含失败、效应量中位数与方向一致率、课题内 FDR 校正、警告聚合），
    结论分级 supported/refuted/mixed/insufficient-evidence，平台建议可降
    不可升；不做跨实验 p 值合并（异质+共享数据，独立性不成立）。
    （→ 详设 §6.4.2，阶段 5 落地）

### 遗留问题（数据线启动时再定）

- "年度龙头"的判定规则：需要哪些历史数据（市值？成交额？行业排名？）、
  TickFlow 能否提供历史市值——待验证；
- TickFlow 是否提供已退市股票历史日 K——待实测；拿不到则池子降级 +
  报告标注幸存者偏差；
- 历史拉深的配额成本与节奏。
