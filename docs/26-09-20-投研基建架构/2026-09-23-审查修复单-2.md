## 2. R2（中）：§6.1.4 的实验形态表缺 head_to_head

**位置**：详设 §6.1.4，「先区分两类实验（一等区分，不是例外）」表格之后、"**原理**：单变量纪律…"那段之前。
**现状原文（表）**：

```
先区分两类实验（一等区分，不是例外）：

| | 创建型实验 | 改进型实验 |
|---|---|---|
| 对象 | 整个策略 | 一个改动 |
| 基准 | `blank-base@1`（空白基准：七插槽全 none，不产生交易） | 策略线上的某个已入库版本 |
| diff | **七槽全填（合法，不降档）** | 强制单槽 |
| 对照 | benchmark 怀疑阶梯（买入持有/60-40/SMA200…） | 基准策略（算 deltas） |
| 回答的问题 | "这个策略整体值不值得存在" | "这个改动有没有用" |
```

**问题**：决策 E5 的 `head_to_head` 只写在 §6.1.2 的规则里；§6.1.4 作为"实验形态"的主表仍只有两行，读者会以为只有两种形态。
**改法**：表格保持不变（它是"两类对比"的两列表），在表格之后、原理段之前**插入**：

```
**第三种形态（二期实现，决策 E5）**：`head_to_head`——策略 A 与策略 B
直接对照（对照 = 另一策略版本，deltas 互算，不走 blank-base 与 benchmark
阶梯）。适用场景："两条策略线谁优"；spec 的 base 字段指定策略 A、增加
ref 字段指定策略 B（字段命名实现时定义）。规则见 §6.1.2"形态预留"。
```

**验收**：§6.1.4 出现 head_to_head 段；与 §6.1.2 互指且无口径冲突。

## 4. R4（低）：运行期数据冻结缺"冻结判据"

**位置**：详设 §3.1「运行期数据冻结（决策 A3）」条。
**现状原文**：

```
- **运行期数据冻结（决策 A3）**：回测运行期间冻结数据写入——调度器在
  run 执行期间顺延日更/指标重建等写任务（run 优先、日更等待），防止
  qfq 原位重写导致一次 run 读到两版数据、血缘失真。实盘运行器例外
  （它的职责就是用最新数据，14:00 执行与 16:30 日更天然不冲突）。
```

**问题**：并发池为 2~4 位，"运行期间"未说明粒度——是单 run 期间冻结，还是存在任意活跃 run 就冻结？两种语义影响调度行为。
**改法**：在该条末尾（"…天然不冲突）。"之后）**追加**：

```
  冻结判据为**计数型**：只要并发池中存在任意活跃回测 run 即冻结写任务，
  全部 run 结束后解冻（多个并发 run 共享同一次冻结，不做逐 run 粒度）。
```

**验收**：冻结粒度明确；与 §6.7"并发隔离（2~4 位）"不冲突。

```

   两只中，第 3 名收盘涨停 → engine_unfilled(reason=limit_up)，第 2 名
   正常成交（fill 落库）；
```

**验收**：步骤 4 与步骤 5 的标的数量、指代一致。
