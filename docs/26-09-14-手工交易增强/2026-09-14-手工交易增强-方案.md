## 2. 数据口径

### 2.1 后端新增字段（`services/trade_records.list_trades`）

| 字段 | 属于 | 口径 |
|---|---|---|
| `mini_chart.dates` / `.candles` | 持仓行 | 窗口 = 最近 20 根日K；买入更早时左扩到买入那一根（保证买点可见），最多 120 根。`candles` 为 ECharts K线序 `[open, close, low, high]`，保留 4 位小数 |
| `mini_chart.buy` | 持仓行 | `{date, price, index}`；`index` = 买点在窗口内的下标（买入日早于窗口时为 `null`，前端退化为买入价横线） |
| `latest_price` / `latest_date` | 清仓行 | 标的**当前**价（盘中为实时报价合成价，否则最新 EOD 收盘），与持仓行现价同源；不按清仓日截断 |
| `since_close_pct` | 清仓行 | `(现价 / 清仓价 − 1) × 100`，2 位小数 |

- 盘中合成K线复用 `compute_manual_trade` 已归一化的 `stops.intraday_bar`（持仓 mini 图）与
  `fetch_intraday_bars` 的批量报价结果（清仓现价），**不新增任何逐标的行情请求**。
- 全量日K按 symbol 预取去重：持仓（指标 + mini 图）与清仓（截止日指标 + 当前价）共用同一份
  `dfs`，同一标的整个请求只读一次（此前已清仓交易每笔各自 `load_market_data`）。
- 批量报价预取现在覆盖**已清仓标的**（原仅持仓标的），仍是同一次批量请求，
  仍满足「整个列表只发一次批量报价」的限流防护约束（`test_batch_prefetch_covers_closed_symbols`）。

### 2.2 止损线取哪一条

mini 图只画**一条**止损线 = `max(硬止损价, 吊灯止损价)`（更高者更紧、先触发），
与页面「风险」列、标的查看页「我的止损」线完全同口径；硬止损/吊灯止损的各自价格与
计算过程仍在表格两列（含悬停明细）里看。

### 2.3 统计口径

- 仅统计**指标计算成功**的清仓行（`error` 行无盈亏/持有天数，计入会污染均值）。
- 胜率 = 盈利笔数 / 清仓次数（盈亏恰好为 0 的笔不计入盈利）。
- 平均盈利 / 平均亏损 = 盈利（亏损）金额之和 ÷ 盈利（亏损）笔数（金额口径，非比例）。
- 平均持股天数按交易日计；交易股票数按标的去重。
- 区间内无盈利（亏损）笔时，平均盈利（亏损）与最大盈利（亏损）显示 `—`，
  避免把「唯一一笔是小亏」显示成「最大盈利 −¥283.50」这种反直觉读数。

### 2.3 已落库记录不再做「买入日区间」回放校验（伴随修复）

实测时发现一个**既有**问题：`561580.SS` 在 2026-09-13 除权，应用启动时
`data.service` 侦测到 ex-factor 变化（日志：`ex-factor changes detected for 3 symbols`）
并重新物化了前复权历史 —— 2026-08-19 当日前复权区间从录入时的 `[1.235, 1.245]`
缩放成 `[1.2263, 1.2362]`，于是**录入时合法**的成交价 1.2411 在回放时越界，
`compute_stop_loss` 抛错 → 整行指标（现价/盈亏/止损/mini 图）全部消失，
该笔也从清仓统计与热力图里掉出去。

改动：`compute_stop_loss` / `compute_manual_trade` 新增 `validate_price: bool = True`；
交易记录列表与标的查看页标注（`trade_records.list_trades` / `symbol_annotations`）
按 `validate_price=False` 调用 —— 已落库的价格是既成事实，只在**录入**时校验。
录入接口 `/api/trades/create`、试算 `/api/evaluate`、MCP 计算仍走默认 `True`，
输入校验强度不变（既有测试 `test_price_out_of_day_range_rejected` /
`test_create_price_out_of_range_400` 继续覆盖）。

> 注意残留口径风险：这类「跨除权」的持仓，其成本价仍是除权前口径，
> 当前价是除权后口径，页面盈亏会带约一个分红比例的偏差（本例 ~0.7%）。
> 彻底解法是录入时固化复权因子、或按当前口径回算历史成交价 —— 属数据模型改动，
> 本次未做，见 §6。

## 4. 交互细节

### 4.1 清仓统计
- 卡片沿用页面既有 `.mt-stat` 家族（与试算区止损卡片同一视觉），总盈亏为主卡（放大 + 高亮）。
- **9 张卡固定挤在一行**（`grid-template-columns: repeat(9, minmax(0,1fr))`，字号/内边距为单行密度收敛），
  不换行；手机端（≤760px）9 列会碎成不可读，改回自动换行。
- 每张卡都有悬停算式（如「胜率 = 盈利笔数 / 清仓次数 = 3 / 13 = 23.08%」）。

### 4.2 持仓 mini 日K图
- 每行一个 ECharts 实例（180×54，手机 150×48），`grid` 留出上下各 12/6px 放标注。
- y 轴范围 = K线高低点 ∪ {买入价, 止损价} + 8% 余量 —— 保证买点与止损线**永远在图内**。
- 买点：`[该根K线, 买入价]` 上一个紫色圆点（白描边 + 阴影，压在红绿蜡烛上也认得出），
  **不写价格文字**（用户 2026-09-14 反馈：图内文字压住K线反而干扰；价格看「买价」列，
  或悬停买入那一根时的「★ 买入 …×份数」一行）。
- 止损线：灰虚线（`#4b5563`）+ 左端实心药丸标签「止损 1.224」；买入那一根滑出窗口（超长持有被 120 根上限截断）时，
  退化为一条**无文字**的紫色点线（全图唯一紫色元素即买点价位，具体价格在悬停提示末行给出）。
- 悬停：该根K线开/收/低/高 + 涨跌幅（盘中最后一根为实时合成K线，日期即当日）；
  悬停到买入那一根额外给「★ 买入 …×份数」。
- 悬停提示**放在图外**：图只有 180×54，压在图内会把K线整块盖住（且半透明底会把图内
  的「买 x.xxx / 止损 x.xxx」文字透出来叠字）。做法是 `tooltip.appendToBody: true` +
  自定义 `position`：优先贴图下方 6px、左沿对齐，窗口底部放不下时翻到图上方。
  注意 ECharts 5 的 `position` 回调**返回的是容器局部坐标**（与入参 point 同空间），
  且本版传入的 `rect` 为 null —— 容器位置只能自己从元素 `getBoundingClientRect()` 取。
- 重渲染（排序 / 筛选 / 刷新 / 切换止损松紧）前统一 `dispose()`，窗口尺寸变化时统一 `resize()`。

### 4.3 已清仓盈亏热力图
- 取 `|realized_pnl|` 最大的 20 只（不足 20 只全取），面积 ∝ `|盈亏金额|`。
- 配色沿用全站涨跌口径：**红 = 盈利 / 绿 = 亏损**（与表格 收益/收益率 列、`metric-positive/negative` 一致；
  需求示意图用的是蓝-红，这里按站内一致性优先取红绿）。
- 标签两遍渲染：先铺出 treemap 真实布局，再按每块实际矩形算字号/换行（同标的看板热力图套路），
  自小而大依次退让：名称（最多两行）→ 盈亏比例 → 盈亏金额。
- 悬停显示：标的 + 代码 + 买卖日期、盈亏金额/比例、买入→卖出价、份数、持有天数、清仓后距今；
  底部注明排序与面积口径。
- 时间范围变化 → 表格/统计/热力图三者同源重算（已 E2E 验证：收窄到 09-01~09-05 后热力图只剩 1 只）。

### 4.4 时间范围
- 分段：近三个月（默认）/ 近六个月 / 今年来 / 自定义；自定义展开两个日期输入（闭区间，留空表示不限）。
- 首次切到自定义时用「上一个预设的起点 ~ 今天」预填，避免空区间导致误以为没数据。
- 纯自然日口径（与旧实现一致，不按交易日数量或当月天数折算）。

## 6. 已知取舍

1. **清仓行现价为「最新可得价」**，非严格意义的逐笔实时价：盘中取批量报价合成价，
   盘后/非交易日取最新 EOD 收盘；悬停里注明取值日期。
2. **持仓表更宽**（新增 日K 180px + 清仓表新增 清仓后距今）：桌面端表格容器是
   `overflow-x: clip`（为保证表头吸顶），窄于约 1850px 的窗口右侧列会被裁掉——
   与既有 17 列的处境一致，手机端有横向滚动兜底。宽屏（用户显示器 ~2048）不受影响。
3. **热力图取前 20 只**：极端分散的小额盈亏不进热力图（表格里仍可见）。
4. **mini 图超长持有上限 120 根**：超过则买点退化为买入价横线，窗口回到「最近 20 根」语义。
5. 热力图配色未采用需求示意图的蓝-红，改用站内红涨绿跌口径（可回退，见 §4.3）。
6. **跨除权的历史成交价未换算**（§2.3）：录入时固化复权因子 / 按当前口径回算历史成交价
   是正确解法，但属数据模型改动（涉及 `manual_trades` 增列与存量数据回填），本次未做。
   现状是「记录不再消失，但这类持仓的成本价与现价不完全同口径」。
